# ADR-002: Technology stack

Status: Accepted, 2026-11-03 (D-002)

## Context
The brief leaves the stack open. The core guarantee will live in the database, so the application language is a secondary choice.

## Decision
Python 3.12, FastAPI, psycopg 3 (async) with SQLAlchemy 2 Core, Alembic, PostgreSQL 16 with `btree_gist`. Tests: pytest, pytest-asyncio, testcontainers. Docker Compose for local running.

Rationale:
- The author's strongest stack gives the best-verified outcome in three days.
- FastAPI emits the OpenAPI contract the brief requires.
- Python with PostgreSQL is a common pairing for a service of this shape.
- The design is portable.

## Alternatives rejected
- NestJS/TypeScript: equally defensible; not chosen because the author's strongest stack gives the better-verified outcome in three days.
- JVM: slower to iterate.
- Full ORM: hides the SQL on which the guarantee depends. Core keeps it explicit.

## Consequences
The design is portable: the constraint, schema and contract test are language-independent, and the port maps to an interface in NestJS or on the JVM.
