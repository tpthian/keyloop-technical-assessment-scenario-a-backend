# ADR-005: Continuous time ranges, not slots

Status: Accepted, 2026-11-03 (D-012, D-026, D-032)

## Context
Service durations vary. The calendar needs a time model.

## Decision
`appointment(start_at, end_at)` with `end_at = start_at + service_type.duration_minutes`, computed server-side. Duration is an elapsed absolute duration, added in UTC, and a service may span days, so the appointment holds its bay and its technician for the whole span. Ranges are half-open, so back-to-back appointments do not conflict; there is no turnaround buffer between jobs. `CHECK (end_at > start_at)` rejects empty ranges.

## Alternatives rejected
- Fixed slot grid: a multi-slot service reserves several rows, which reintroduces atomicity across rows; odd durations fit badly.
- Duration as working hours walked over the calendar: right for labour, wrong for curing or parts waiting, and heavy arithmetic.
- Technician held per working day, bay held for the span: several rows per appointment, the multi-row atomicity the slot grid was rejected for.

## Consequences
One row per appointment, so one INSERT is the whole reservation and a range exclusion constraint expresses the rule directly. Availability search returns, per (bay, qualified technician) pair and local day, start windows, not slot IDs: the free interval with the duration subtracted from its right end on UTC instants, then intersected with the local opening hours (ADR-010).
