# ADR-006: Qualification model

Status: Accepted, 2026-11-03 (D-013)

## Context
A booking needs a "qualified" technician. The brief does not define qualification.

## Decision
One required skill per service type today, in a schema that supports several: `skill`, `technician_skill(technician_id, skill_id)`, `service_type_required_skill(service_type_id, skill_id)`. A technician is qualified when they hold all skills the service type requires. Bays are skill-agnostic. No skill-management API; seed data only.

## Alternatives rejected
- Skill column on technician: cannot express several skills without migration.
- Skill levels, certifications, expiry now: speculative; they are additive columns on the join tables later.

## Consequences
Moving to multi-skill services needs data, not schema change. Bay types remain future work.
