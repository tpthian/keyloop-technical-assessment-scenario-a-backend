# ADR-003: The scheduler owns the resource calendars

Status: Accepted, 2026-11-03 (D-009; reconciled with D-016)

## Context
The first sketch put bay and technician availability in a separate "ServiceBay service", with the scheduler asking it before confirming.

## Decision
Bays, technicians, skills and the appointment calendar live inside the scheduler's bounded context. Dealership master data may be referenced by ID from elsewhere; the scheduler holds a seeded local copy of the time zone and opening hours it needs, keyed by dealership ID.

- Rule: the local copy holds only what the scheduler needs to validate a booking. It reconciles D-009 (master data stays elsewhere) with D-016 (hours and zone are stored here).
- Rationale: the service that owns an invariant owns the data the invariant ranges over.

## Alternatives rejected
- Separate availability service: "check then confirm" becomes a cross-service write with no shared transaction, so the no-double-booking guarantee turns into a saga or reservation protocol.

## Consequences
The guarantee is a single-database property (ADR-004). Replacing a manual booking system means replacing the workshop calendar, which this boundary matches.
