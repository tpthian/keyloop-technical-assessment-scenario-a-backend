# ADR-001: Scenario and implementation layer

Status: Accepted, 2026-11-03 (D-001)

## Context
The brief offers four scenarios and asks for one service layer (backend or frontend) to be implemented.

## Decision
Scenario A, the Unified Service Scheduler, backend only. The client is stubbed with the OpenAPI contract, curl examples and a demo script.

## Alternatives rejected
- Scenarios B, C, D: dashboards, CRUD and aggregation. None has a hard, testable correctness property to reason about.
- Frontend for Scenario A: would demonstrate the weaker half of the problem; the guarantee is a backend property.

## Consequences
The submission can be judged on a provable property (no double-booking under concurrent requests). No UI exists; see ADR-012.
