# Decision register

This register resolves every decision id (D-nnn) that the design document, the ADRs, the SPEC, the code, the tests and the review files cite. Ids are numbered in the order the decisions were made; a gap in the sequence is a decision that no file in the repository cites. Each row states the decision as it stands, where it came from, and the document that carries the rule today. Where a later decision amends or supersedes an earlier one, both rows say so. The working log that holds the discussion behind each decision (context, options, rationale) stays outside the repository, as step 3 of the [pipeline](ai/README.md#how-the-pipeline-runs) states; the restating document carries the rationale the code depends on.

Origin names where a decision came from; the author decides every entry ([roles](ai/README.md#roles)), so origin records the source of the proposal and how it was disposed of. `brief`: the challenge document requires it. `author`: the author's own position or ruling. `AI, accepted`: proposed by AI, as a challenge or a concrete proposal, and accepted by the author. `review, accepted`: found by an adversarial review, a second-model review or a code audit, and accepted. `author, overriding AI`: the author struck or reversed an AI proposal; the row states the result.
